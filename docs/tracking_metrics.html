Tracking metrics reference

Definitions for motion-tracking quality metrics used in Isaac Lab training, Genesis sim2sim evaluation, and transfer-validation tooling. Primary implementation: scripts/sim2sim_genesis/metrics.py.

1. Where metrics appear

ContextModuleWhen computed
Genesis closed-loop sim2sim sim2sim_genesis/metrics.py via Sim2SimRunner Each control step during ONNX policy rollout in Genesis (--compute_metrics)
Legacy monolithic evaluator scripts/rsl_rl/evaluate_sim2sim_genesis.py Same semantics as modular metrics; duplicated helpers for backward compatibility
Isaac Lab training / play tasks/tracking/mdp/commands.py, rewards.py Each env step inside MotionCommand._update_metrics() and PPO reward terms
Open-loop transfer replay sim2sim_genesis/openloop_replay.py Per trajectory after Isaac→Genesis base-only replay (not in metrics.py)
Reference vs prediction. In closed-loop sim2sim, the reference is the trajectory emitted by the exported ONNX policy at each time_step (joint/body states embedded in the graph). The prediction is the actual Genesis robot state after PD control. In Isaac training, reference comes from the motion NPZ and prediction from the simulated robot.

2. Coordinate conventions

2.1 Anchor body

Most tracking metrics compare an anchor link (typically torso_link on G1, configured as anchor_body_name in ONNX metadata and the motion command). Anchor position/orientation errors are computed in world frame.

2.2 Yaw-aligned relative body targets

Body pose rewards and error_body_pos / error_body_rot use relative targets built in TrackingMetricsEvaluator.compute_body_relative_targets() (mirrors Isaac MotionCommand logic):

  • Horizontal position: align reference bodies to the robot anchor XY, keep reference anchor height Z.
  • Orientation: apply yaw-only delta between robot and reference anchor quaternions.
  • Result: body_pos_relative, body_quat_relative — “what the bodies should be if the robot matched reference anchor height and yaw.”
world reference bodies │ ▼ yaw-only + XY anchor alignment body_pos_relative ──compare──► robot body_pos_w (world)

2.3 Root index for MPJPE

compute_metrics_lite(..., root_idx=0) subtracts body index 0 (pelvis / root link in policy body order) before computing local MPJPE. Rollout summaries additionally apply a spatial offset alignment at t=0 so parallel env spacing does not inflate global MPJPE.

3. Per-step tracking errors (tracking_metrics)

TrackingMetricsEvaluator.tracking_metrics(state, reference) returns scalar errors for one env at one timestep. Shapes: state/reference dicts hold joint_* vectors and per-body body_*_w arrays indexed by policy body_names.

KeyDefinitionUnits
error_anchor_pos ‖p_ref_anchor − p_robot_anchor‖₂ m
error_anchor_rot Quaternion error magnitude between reference and robot anchor orientations rad
error_body_pos Mean over bodies of ‖body_pos_relative − body_pos_robot‖₂ m
error_body_rot Mean over bodies of quaternion error between relative target and robot body orientations rad
error_joint_pos ‖q_ref − q_robot‖₂ (Euclidean norm over all policy joints) rad
error_joint_vel ‖q̇_ref − q̇_robot‖₂ rad/s

Isaac MotionCommand._update_metrics() logs the same error family plus error_anchor_lin_vel, error_anchor_ang_vel, error_body_lin_vel, and error_body_ang_vel (not exported as scalars from tracking_metrics, but used in reward exponentials below).

4. Reward-shaped terms (rew_tracking_*)

Genesis metrics mirror Isaac exponential tracking rewards from tracking_env_cfg.py / rewards.py. Each term is exp(−error / std²) in [0, 1], higher is better.

KeyIsaac reward namestdWeight in total
rew_tracking_anchor_pos motion_global_anchor_pos 0.3 m 0.5
rew_tracking_anchor_ori motion_global_anchor_ori 0.4 rad 0.5
rew_tracking_body_pos motion_body_pos (relative) 0.3 m 1.0
rew_tracking_body_ori motion_body_ori (relative) 0.4 rad 1.0
rew_tracking_body_lin_vel motion_body_lin_vel 1.0 m/s 1.0
rew_tracking_body_ang_vel motion_body_ang_vel 3.14 rad/s 1.0
tracking_reward_total = 0.5·rew_tracking_anchor_pos + 0.5·rew_tracking_anchor_ori + rew_tracking_body_pos + rew_tracking_body_ori + rew_tracking_body_lin_vel + rew_tracking_body_ang_vel

During Genesis rollout, Sim2SimRunner accumulates per-step values and reports {key}_mean in the output JSON (divided by total steps). Maximum per-step tracking_reward_total is 5.0 when all exponentials equal 1.

5. Termination checks

TrackingMetricsEvaluator.termination_check() mirrors Isaac TerminationsCfg.anchor_pos / anchor_ori thresholds used during metric rollouts:

Reason stringConditionIsaac threshold
anchor_pos_z |z_ref_anchor − z_robot_anchor| > 0.5 Training uses 0.25 m (stricter); metrics use 0.5 m in Genesis code
anchor_ori |Δ projected gravity z| > 0.8 between reference and robot anchor Same 0.8 threshold in Isaac bad_anchor_ori
completed No termination triggered —

Returned fields: terminated (0/1 float) and termination_reason (string). Multi-env metric collection tracks per-env end steps when termination fires early.

6. Trajectory-level pose metrics (compute_metrics_lite)

ASAP-style metrics on body position sequences, shape [T, B, 3]. Used at end of each metric rollout in Sim2SimRunner (after root-offset alignment).

KeyNameDefinitionUnits
mpjpe_g MPJPE global Per-frame, per-body Euclidean distance in world frame; ×1000 mm
mpjpe_l MPJPE local Same after subtracting root body position at each frame mm
vel_dist Velocity distance Mean over bodies of ‖Δp_pred − Δp_ref‖ on finite differences; ×1000 mm/frame
accel_dist Acceleration distance Mean over bodies of central-difference acceleration error; ×1000 mm/frame²
mpjpe_g[t,b] = 1000 · ‖p_ref[t,b] − p_pred[t,b]‖₂ mpjpe_l[t,b] = 1000 · ‖(p_ref[t,b] − p_ref[t,root]) − (p_pred[t,b] − p_pred[t,root])‖₂

JSON export reports mpjpe_mean, mpjpe_l_mean, vel_dist_mean, accel_dist_mean plus _std and _succ_* variants aggregated over rollouts. A rollout counts as success when it runs within 5 steps of max_steps.

7. Isaac-only logged metrics

During training/play, MotionCommand.metrics also tracks sampling diagnostics (not in Genesis metrics.py):

  • sampling_entropy — normalized entropy of adaptive motion-bin sampling probabilities
  • sampling_top1_prob — largest bin probability
  • sampling_top1_bin — normalized index of the top bin

8. Open-loop transfer metrics

When comparing Isaac source states to Genesis base-only replay (openloop_replay.py / replay_openloop_genesis.py), metrics differ from closed-loop tracking — they measure cross-simulator state drift, not ONNX reference tracking.

KeyDefinitionUnits
rmse_abs RMSE of joint position: Genesis replay vs Isaac source rad
rmse_rel RMSE after subtracting each side’s default joint pose rad
max_abs / max_rel Max absolute joint error (absolute / relative) rad
body_rmse / body_max RMSE / max of world-frame body_pos_w error m

10. Quick interpretation guide

  • Low error_body_pos — robot keypoints match yaw-relative motion targets.
  • High tracking_reward_total — same information as rewards, useful for comparing simulators step-by-step.
  • Low MPJPE (mm) — good whole-body pose match over a rollout; local MPJPE ignores global translation.
  • termination_reason ≠ completed — fall / orientation failure; rollout may be truncated in metric aggregation.
  • Transfer rmse_rel — primary joint metric for Isaac(base+δ) vs Genesis(base) validation; lower is better.
