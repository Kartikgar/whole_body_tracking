Play evaluation workflows

How scripts/rsl_rl/play.py evaluates policies in Isaac Lab, what gets exported to ONNX, and how that connects to Genesis sim2sim evaluation for the three main policy types in the Delta-A pipeline.

What this document covers

This repo has three distinct evaluation stories that all go through play.py for in-Isaac rollout, but differ in task config, observation space, action composition, and what you deploy in Genesis:

  1. Pre-trained base policy — standard motion tracking (Tracking-Flat-G1-v0)
  2. Open-loop delta policy — dynamics emulator trained with motion actions (Tracking-Flat-G1-DeltaA-OpenLoop-v0)
  3. Finetuned base policy — tracking policy trained with frozen delta assistance (Tracking-Flat-G1-DeltaA-Finetune-v0)

Related docs: genesis_sim2sim_evaluator.html, delta_action_finetuning_implementation.md, project_understanding.md.

Shared setup in play.py

Regardless of policy type, play.py follows the same outer shell:

  1. Parse CLI args and load Hydra task config via @hydra_task_config.
  2. Resolve checkpoint from --checkpoint, --wandb_path, or log directory.
  3. For motion tasks: disable adaptive reference sampling for deterministic playback.
  4. Optionally override --motion_file, --delta_action_space, --disable_dr.
  5. Create Isaac env, wrap with RslRlVecEnvWrapper.
  6. Load checkpoint via MotionOnPolicyRunner (same class used in training).
  7. Export ONNX from the loaded actor to {checkpoint_dir}/exported/.
  8. Run the rollout loop; optionally record video or delta-model dataset NPZ.
CLI + Hydra task config | v env_cfg overrides (motion, DR, delta action space) | v gym.make(task) --> RslRlVecEnvWrapper | v MotionOnPolicyRunner.load(checkpoint) | +--> export ONNX (actor only) | v rollout loop --> env.step(actions) | v optional: video / delta dataset / cleanup buffers

Deterministic motion playback

For any task with a motion command, play always sets: 

env_cfg.commands.motion.adaptive_alpha = 0.0
env_cfg.commands.motion.sample_time_steps = False

Evaluation runs the reference motion sequentially from the start instead of using training-style adaptive resampling.

Runner and ONNX export

All three flows use MotionOnPolicyRunner. ONNX export always serializes ppo_runner.alg.policy — the checkpoint you loaded — plus observation metadata from the env. It does not export a composed two-policy controller.

Policy typeWhat ONNX containsWhat Genesis runs
Pre-trained base Base tracking actor Same base actor
Open-loop delta Delta actor (132-d obs incl. motion_joint_action) Same delta actor + motion NPZ actions
Finetuned base Finetuned base actor only Base actor only (no frozen delta)
Deployment intent for Delta-A finetune: the frozen delta policy is a training-time dynamics emulator. At inference you deploy only the finetuned base policy. Isaac finetune play still runs base + frozen delta to match training rollouts; Genesis sim2sim tests base-only under perturbed Kp/Kd.

1. Pre-trained base policy evaluation

This is standard BeyondMimic-style whole-body tracking. The policy closes the loop on reference motion using anchor-relative observations and outputs joint position targets directly.

Isaac play flow

motion command (reference pose/vel) | v build policy obs (command, anchor error, proprioception, last_action) | v a_base = base_policy(obs) | v env.step(a_base) --> q_target = scale * a_base + offset

Policy observation (policy group)

From TrackingEnvCfg.ObservationsCfg.PolicyCfg:

  1. command — generated motion command
  2. motion_anchor_pos_b — reference anchor position in robot base frame
  3. motion_anchor_ori_b — reference anchor orientation (first two columns of rotation matrix)
  4. base_lin_vel, base_ang_vel
  5. joint_pos, joint_vel (relative to default)
  6. actions — previous base policy action (last_action)

This group has observation corruption enabled during training; use --disable_dr for clean eval.

Example Isaac command

python scripts/rsl_rl/play.py \
  --task Tracking-Flat-G1-v0 \
  --checkpoint /path/to/base_model.pt \
  --motion_file /path/to/walk1_subject1.npz \
  --num_envs 4 \
  --disable_dr \
  --video

Genesis sim2sim flow

Genesis state + reference motion from ONNX metadata | v rebuild base policy obs (same term order as export metadata) | v a_base = ONNX(a_base_obs) | v q_target = scale * a_base + offset | v PD torques with perturbed Kp/Kd --> scene.step()

See genesis_sim2sim_evaluator.html for PD loop, Kp/Kd perturbation, metrics, and domain randomization details.

Alignment: Isaac play and Genesis sim2sim run the same controller — one base policy, same obs layout, same action post-processing. Poor Genesis performance here means direct sim-to-sim transfer failure under target actuator dynamics.

2. Open-loop delta policy evaluation

The open-loop delta policy is trained as a dynamics correction emulator. It does not track motion via anchor observations. Instead it sees proprioceptive state plus the recorded open-loop motion action from the NPZ, and outputs a delta correction that is added to that motion action before PD control.

Isaac play flow

motion NPZ provides joint_action[t] (open-loop reference) | v build delta policy obs (proprio + contact + last_delta + motion_joint_action) | v a_delta = delta_policy(obs) | v env.step(a_delta) | v q_target = scale * (a_delta + motion_joint_action[t]) + offset

In this mode ppo_runner.delta_policy is None. The loaded checkpoint is the delta policy. There is no second frozen policy branch in the play loop.

Delta policy observation (DeltaOpenLoopPolicyObsCfg)

Terms are concatenated in this order (approx. 132-d for whole-body G1):

TermDim (typical)ScaleMeaning
base_pos_z11.0Root height
feet_contact_force60.01Left/right ankle contact forces (world frame)
base_lin_vel32.0Base linear velocity
base_ang_vel30.25Base angular velocity
projected_gravity31.0Gravity in base frame
joint_pos291.0Joint positions relative to default
joint_vel290.05Joint velocities
actions291.0Previous delta output (last_action)
motion_joint_action291.0Open-loop action from motion NPZ at current time index

Notably absent from the actor: command, motion_anchor_pos_b, motion_anchor_ori_b. The critic during training does receive full motion/command terms for value estimation only.

Per-step play loop (simplified)

policy_actions = policy(obs)          # delta policy
actions = policy_actions                # passed to env.step
obs, _, dones, _ = env.step(actions)   # env adds motion_joint_action internally

Example Isaac command

python scripts/rsl_rl/play.py \
  --task Tracking-Flat-G1-DeltaA-OpenLoop-v0 \
  --checkpoint /path/to/delta_open_loop_model.pt \
  --motion_file /path/to/motion_with_actions.npz \
  --num_envs 4 \
  --disable_dr \
  --video
Motion file requirement: open-loop delta evaluation requires an NPZ with action or actions. Without it, DeltaJointPositionAction raises at runtime and motion_joint_action cannot be built.

Genesis sim2sim flow

Genesis state | +--> rebuild delta obs (proprio + contact + last_delta) | motion NPZ action[t] --> motion_joint_action term | v a_delta = ONNX(delta_obs) | v q_target = scale * (a_delta + motion_action[t]) + offset | v PD torques (perturbed Kp/Kd) --> scene.step()

Genesis detects motion_joint_action in ONNX metadata and requires --motion_file with action arrays. The evaluator feeds recorded motion actions into the observation builder each step, matching Isaac open-loop semantics.

Debug flags useful for delta eval

  • --replay_motion_actions_only — zero policy output; env still applies motion action (tests NPZ replay alone).
  • --record_delta_model_dataset — log obs/action trajectories for retraining delta models.
  • --delta_action_space ankles|lower_body|com_force — evaluate subset or COM-force delta modes.

3. Finetuned base policy evaluation

Finetune training keeps a frozen open-loop delta policy active during rollouts so the base policy learns under assisted dynamics. Evaluation has two distinct meanings:

  1. In-Isaac play — validates finetuned base under the same assisted dynamics used in training.
  2. Genesis sim2sim — validates deployment-style base-only control in the target environment.

Isaac play flow (assisted dynamics)

build base policy obs --> a_base = finetuned_base(obs) | | runner injects a_base into delta_base_actions buffer v build delta_policy obs: - actions = previous frozen delta (delta_external_actions) - current_action = same-step a_base (delta_base_actions) | v a_delta = frozen_delta_policy(delta_obs) | | runner injects a_delta into delta_external_actions buffer v env.step(a_base) --> q_target = scale * (a_base + a_delta) + offset

Per-step play loop (finetune branch)

policy_actions = policy(obs)                     # finetuned base
actions = policy_actions

ppo_runner._set_delta_base_action_buffer(actions)
delta_obs = ppo_runner._compute_delta_policy_obs()
delta_actions = ppo_runner._compute_delta_actions(delta_obs)
ppo_runner._set_delta_action_buffer(delta_actions)

obs, _, dones, _ = env.step(actions)             # base action only; env adds external delta

env.step always receives the base action. Composition happens inside ExternalDeltaJointPositionAction.

Two observation groups at runtime

Base policy (policy group)

Same motion-tracking layout as pre-trained base (command, anchor error, proprioception, last base action).

Frozen delta policy (delta_policy group, DeltaPolicyObsCfg)

TermSourceMeaning
base_pos_z … joint_velEnv sensorsSame proprio/contact block as open-loop delta
actionsdelta_external_actionsPrevious frozen delta output (autoregressive channel)
current_actiondelta_base_actionsSame-step base policy action injected by runner

Compared to open-loop delta obs, motion_joint_action is replaced by current_action (live base output). Layout and scales otherwise match so the frozen delta checkpoint stays compatible.

Time alignment at step t

Delta input at step t:   (δt−1,   abase,t)  →  frozen policy  →  δt
Env command at step t:   abase,t + δt (before scale/offset)

Example Isaac command

python scripts/rsl_rl/play.py \
  --task Tracking-Flat-G1-DeltaA-Finetune-v0 \
  --checkpoint /path/to/finetuned_model.pt \
  --delta_policy_checkpoint /path/to/open_loop_delta_model.pt \
  --motion_file /path/to/walk1_subject1.npz \
  --num_envs 4 \
  --disable_dr \
  --video
Required for finetune play: --delta_policy_checkpoint must point to the frozen open-loop delta checkpoint. The finetune run's params/agent.yaml contains this path, but play.py does not auto-load it — pass it explicitly unless you override via Hydra.

ONNX export after finetune play

Export uses ppo_runner.alg.policy — the finetuned base actor — with base policy obs metadata. The frozen delta branch is excluded. That ONNX is the deployment artifact for Genesis.

Genesis sim2sim flow (deployment-style)

Genesis state + reference motion from ONNX metadata | v rebuild base policy obs (motion-tracking layout) | v a_base = ONNX(base_obs) # no delta branch | v q_target = scale * a_base + offset | v PD torques with perturbed Kp/Kd --> scene.step()
Why two eval modes matter: good Isaac finetune play + poor Genesis sim2sim means the base policy works in assisted source dynamics but not in true target dynamics. That is the central sim2real gap Delta-A is trying to close.

End-to-end Delta-A pipeline

How the three evaluation modes fit the training stages:

Stage 1: Train open-loop delta Task: Tracking-Flat-G1-DeltaA-OpenLoop-v0 Eval: play.py (delta policy) --> optional Genesis (delta ONNX + motion actions) Stage 2: Finetune base with frozen delta Task: Tracking-Flat-G1-DeltaA-Finetune-v0 Eval: play.py (base + frozen delta in Isaac) Stage 3: Deploy finetuned base only Export: play.py ONNX (base only) Eval: evaluate_sim2sim_genesis.py (base only, perturbed Kp/Kd)

Interpreting results

SymptomLikely meaning
Good base play in Isaac, bad Genesis base eval Sim-to-sim transfer failure under target Kp/Kd; delta-assisted training did not close the dynamics gap
Good open-loop delta play, bad finetune Genesis Delta emulator works in source sim but base did not learn a deployable policy for target dynamics
Good finetune Isaac play, bad Genesis Base relies on assisted dynamics; deployment without delta fails in target env
Finetune play fails immediately Missing --delta_policy_checkpoint or obs-dim mismatch with frozen delta checkpoint
Open-loop play fails on motion NPZ missing action/actions arrays
